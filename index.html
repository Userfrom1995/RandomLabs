About This Repo

Almost all the code here is written, maintained, and reviewed by coding agents, driven from a single random chat. The pipeline operates on a unified event bus using automated /oc comments:

  • Ideator: on-demand creative consultant - posts candidate projects to the Brainstorm Board when summoned by the Maintainer or Owner.
  • Maintainer: orchestrates the lab, evaluates PRs, and merges approved code.
  • Researcher (Dr. Mob): the principal scientist. Designs complex scientific and algorithmic specifications.
  • Architect: designs heavy, creative, and mechanically deep architectural blueprints.
  • Builder/Fixer: builds the code on a branch, tracking state via progress files, and automatically fixes code based on review findings.
  • Reviewer: strictly reviews the PR (including a preview of this site) and loops with the Fixer until it passes.
  • Tester: dynamically runs E2E user flows and visual benchmarks before merging.
  • Linux / macOS / Windows Testers: per-OS real-user QA specialists: test every command, flag, and workflow natively on their OS (/oc test-linux, /oc test-macos, /oc test-windows) and feed per-platform reports to the Tester.
  • Evaluator: autonomous Quality Council / Program Committee: binding quality gate after the Tester (`/oc eval`). Audits empirical rigor, scientific depth, visual craft, baseline parity, adversarial resilience, and reproducibility; commands swarm subagents; writes `/tmp/evaluator-decision.json`.
  • Auditor: the pipeline inspector: monitors the lab health, identifies stalls or crashes, and dispatches fixes.
  • Lab Engineer: the Chief Technology Officer (CTO) & Lab Architect: builds workflows, creates agents, and manages models.
  • Curator: the public surface, web, and README custodian: audits website pages, assets, styling, and README synchronization, opening surgical PRs.
  • Recover Agent: PR survival and continuation engineer. Resurrects closed or orphaned build PRs into open continuation PRs (via /oc recover and the opencode-recover.yml auto-detect job).

Open issues and pull requests show what is currently in flight. To propose an idea, open an issue and tag @Userfrom1995.
