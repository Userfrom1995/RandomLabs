The workflow

From idea to merge, without the grunt work

01

Open an issue

Describe the task or paste a bug report. No ceremony required.

02

Agent takes the wheel

It creates a branch, writes the code, adds tests, and pushes a PR.

03

You stay in control

Review the diff, ask for changes in plain language, approve, merge.

04

Rinse and repeat

Agents learn your style with every cycle, and the loop only gets faster.

.github/workflows/agent.yml 
name: agent-on-pr
on:
  pull_request:
    types: [opened, synchronize]
jobs:
  agent:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - name: Review the diff
        uses: openai/codex-action@v1
        with:
          prompt-file: .github/prompts/review.md

FAQ

Questions, answered

Do I still review the code? +

Always. Agents propose changes; humans approve them. Every merge flows through your existing branch protection and code review rules.

Which languages and frameworks are supported? +

Virtually all of them. Agents read plain code and your repo context, so they work with any language — from Go to Python to TypeScript to Rust.

Is my code safe? +

Agents run inside your repo's own Actions with scoped tokens, never storing your code. Secrets and tokens are never logged or shared.

Can I run agents only on my own terms? +

Yes. You choose which PRs, which events, which paths, and which branches agents act on — configured entirely in your workflow file.
