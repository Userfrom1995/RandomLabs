torshim.

Anything through Tor. One command. No Tor internals to learn.

A lightweight cross-platform Tor CLI. Route a single application through Tor, spawn a Tor-routed shell, or send an entire Linux system through Tor with snapshot-first firewall state and a verify-gated, byte-exact restore. torshim automates the existing tor daemon; it never implements Tor itself.

Three modes

Pick your blast radius

Every mode shares one rule: if Tor is not bootstrapped or not ready, torshim fails closed with a clear error. Where a route could leak but cannot be inspected from outside (apps ignoring proxy env on macOS/Windows, raw syscalls under the shim), torshim does not guess: proxy-mode launches print the coverage note, the shell prints its coverage banner, and the raw-syscall gap is stated in that banner and in the docs. It never reports "protected" when it is not.

One application

Run a single command through Tor. On Linux the app executes under a fail-closed torsocks shim (static binaries and setuid tools are refused, because they would silently bypass it). On macOS and Windows it runs with a socks5h:// proxy environment; every launch prints an honest coverage note.

per-app
torshim curl ifconfig.me
torshim git pull
torshim run -- firefox
Linux: torsocks shim macOS: proxy env Windows: proxy env

A Tor-routed shell

Open a child shell whose processes route through Tor while the parent shell stays untouched. The child carries the shim environment, a [torshim] prompt prefix, and a coverage banner, so you always know what is and is not covered.

shell
torshim shell
# traffic exits via Tor
[torshim] $ curl ifconfig.me
Linux macOS: proxy env Windows: proxy env (needs $SHELL)

The whole system

Send every TCP exit and DNS query on a Linux box through a private Tor instance: iptables or nft capture rules, a snapshot-first backup of the firewall, a five-row verify suite with automatic rollback, and a byte-exact restore on disconnect. IPv6, non-DNS UDP, and ICMP are blocked for the session, never silently passed.

system-wide
sudo torshim connect
torshim status --json
sudo torshim disconnect  # restore
Linux: iptables / nft macOS: honest exit 4 Windows: honest exit 4

Command reference

Every command, in one place

One binary, eight verbs, plus the bare-app shorthand. Bare torshim <app> [args...] is shorthand for run. Run torshim help for the built-in usage text.

torshim <app> [args...]Run one application through Tor (same as run). Flags: --tor BIN, --timeout D, --reuse.
torshim run -- <app> [args...]Explicit form of per-app routing with a separating --.
torshim shellOpen a Tor-routed child shell; the parent shell is unaffected.
sudo torshim connectSystem-wide Tor on Linux. Flags: --backend auto|iptables|nft, --tor BIN, --timeout D, --tor-user USER, --trans-port PORT, --state-dir DIR, --force.
torshim disconnectStop tor first, then replay the pre-connect snapshot byte-exact and post-verify (needs sudo when a session exists).
torshim repairClear stale rules and dead session state; only ever removes torshim-owned rules, never a foreign flush (needs sudo).
torshim status [--json]Is tor running, bootstrapped, circuit ready, which mode is active, endpoint and session state? Flags: --json, --control, --socks, --state-dir. Never claims protected when it cannot prove it.
torshim versionWrapper version plus platform backend, tor, and torsocks versions.
torshim helpUsage text and the platform support summary.

Design principles

Fail closed, never fail friendly

A privacy tool that lies is worse than no tool. Every guarantee below is enforced in code paths, not in marketing copy.

Never falsely claim protection

run and shell refuse to start without a bootstrapped tor (exit 3). connect applies no firewall rule until tor reports bootstrap 100% plus a live circuit, then gates on a five-row verify suite and rolls back on any failure. status reports protected: false for every state it cannot positively confirm: absent, unknown, bootstrapping, or an unreadable foreign control port. A stale system-wide session is reported as a note and never upgrades the mode.

DNS goes through Tor too

Per-app DNS uses SOCKS5 hostname resolution (socks5h://), so names resolve at the exit, not on your resolver. System-wide DNS is captured by REDIRECT into the Tor DNSPort; /etc/resolv.conf is never rewritten, so DHCP cannot clobber the capture. IPv4 and IPv6 leaks are handled explicitly: IPv6 is blocked for the session rather than routed around.

Reversible by construction

connect snapshots the firewall and resolver state before touching anything. disconnect stops tor first (so redirects blackhole instead of leaking), replays the snapshot byte-exact, and post-verifies that no torshim rules remain. Concurrent connect/disconnect/repair runs serialize on a session lock; stale locks from a crash are reaped.

Honest about what it does not cover

On macOS and Windows, only applications that honor proxy environment variables are covered; the coverage note is printed on every launch because the wrapper cannot see an app that ignores it. On Linux, per-app mode refuses static binaries and setuid/setgid tools up front; raw syscalls are not covered by the shim (the coverage banner says so), which is one reason system-wide mode exists. The limitations are documented per OS, not glossed over.

Under the hood

How a session works

The same lifecycle backs every mode: a private, supervised tor instance (or a verifiable reused one), a binding readiness gate, and cleanup that survives Ctrl-C.

  1. Launch a private tor. A mkdtemp data directory with random loopback Socks, Control, and DNS ports, cookie authentication, and __OwningControllerProcess plus TAKEOWNERSHIP, so a crash exits the owned tor instead of orphaning it. A foreign instance can be reused with --reuse, but never killed.
  2. Wait for real readiness. Bootstrap PROGRESS=100 with TAG=done and a live circuit (status/circuit-established == 1), polled within the timeout budget (120 s default).
  3. Route. Per-app: exec under the torsocks shim (Linux) or with socks5h:// proxy environment (macOS/Windows). System-wide: install iptables/nft capture rules redirecting TCP to the transparent proxy port (9040) and port-53 UDP to the Tor DNSPort, while rejecting everything else.
  4. Verify. System-wide mode gates on five checks: tor-ready, rules-present, transport-open, dns-alive, resolv-untouched. Any failure rolls the firewall back and exits non-zero.
  5. Restore. On disconnect: stop tor first, remove only the torshim rules, replay the pre-connect snapshot byte-exact, drop the session state, then post-verify that no rules remain. On rollback after a failed connect: stop tor, remove only the rules just applied, and drop state (the snapshot is kept for forensics; no replay or post-verify). Ctrl-C during a run stops the owned tor before exiting.

Quick start

Build and install

Go 1.24+, standard library only (CGO_ENABLED=0, no go.sum). Runtime dependency: a stock tor binary. Linux per-app additionally needs torsocks; system-wide additionally needs root plus iptables/ip6tables or nft.

build from source
# build from source
git clone https://github.com/Userfrom1995/RandomLabs.git
cd RandomLabs/tor-cli
make build   # static binary ./torshim
make test    # hermetic: no root, no tor, no firewall
sudo make install   # torshim + torshim.1 man page
verify the install
torshim version
torshim status --json   # protected: false until proven
first minutes with torshim
# 1. one app through Tor
torshim curl https://check.torproject.org/api/ip

# 2. a Tor-routed shell
torshim shell

# 3. the whole machine (Linux, root)
sudo torshim connect
torshim status
sudo torshim disconnect   # restore, byte-exact
one-line gates
make build && make test && make vet && make cross
# linux/darwin amd64+arm64, windows amd64
