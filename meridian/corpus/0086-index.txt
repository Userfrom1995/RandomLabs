    <div class="card">

  <h2>How it works</h2>
  <ul>
    <li><strong>Crawl.</strong> Each document becomes one plain-text file plus
    a manifest entry with a stable source path, title (first heading or
    filename), and URL. The output is deterministic: same tree, same corpus.</li>
    <li><strong>Tokenize.</strong> Chars are walked once; <code>\p{L}</code>/
    <code>\p{N}</code> starts a word, apostrophes between letters stay inside
    it, case is folded, and the byte offset of every word boundary is
    recorded so snippets can be byte-exact. CJK runs are split into unigrams
    and bigrams sharing positions.</li>
    <li><strong>Index.</strong> A postings list per term is kept sorted by
    document id; document frequency, term frequency, and positions fall out of
    construction. <code>AND</code> intersects rarest-first, <code>OR</code>
    unions, <code>NOT</code> subtracts, phrases intersect consecutive
    positions. Stemmed queries expand each term to its family; fuzzy leaves
    expand via the BK-tree.</li>
    <li><strong>Compress.</strong> Postings store <code>(doc_id gap, tf,
    position gaps)</code> as LEB128 varints packed into a byte array,
    base64-encoded for JSON. Decoding is the exact inverse;
    <code>verify-index</code> re-encodes and compares.</li>
    <li><strong>Rank.</strong> BM25 scores
    <code>idf * tf*(k1+1) / (tf + k1*(1 - b + b*len/avgLen))</code> and TF-IDF
    scores <code>tf * log(N/df)</code>. Ranked queries sum per-term scores;
    boolean queries compute matches first and rank the surviving set. With
    signals on, title terms get a 1.5x boost and co-located terms a 0.5x
    proximity bonus.</li>
    <li><strong>Snippet.</strong> The best window around the densest cluster
    of matches is chosen, snapped to word boundaries, and returned with the
    byte ranges of every matched term so renderers can highlight without
    re-tokenizing.</li>
  </ul>

  <h2>Design choices</h2>
  <ul>
    <li><strong>From scratch.</strong> No crates, no node packages, no search
    library: the whole pipeline is written against the Rust standard library
    and browser JS. This is what makes the cross-language mirror possible.</li>
    <li><strong>One engine, two languages.</strong> Instead of a web server,
    the ranking, parsing, and snippet logic is ported line-by-line to JS so
    the UI is a static site. A consistency suite keeps the two honest.</li>
    <li><strong>Deterministic end to end.</strong> Crawl order, token
    positions, and scores are fully deterministic; the same command always
    produces the same index and ranked output.</li>
    <li><strong>Self-verifying.</strong> <code>meridian check</code> re-runs
    core invariants at runtime, and the test suite covers every module plus
    the JS mirror.</li>
  </ul>
