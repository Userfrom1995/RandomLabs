Beambus

A retro arcade shoot 'em up written in Zig: a deterministic, headless-testable game core, scripted .beam levels, six enemy movement patterns, configurable enemy shot volleys, power-up weapon tiers and one-hit shields, smart bombs, a combo scoring multiplier, bonus lives, near-miss grazes, a procedural pixel-art renderer, and a tiny subtractive audio synth, all on an SDL2 platform layer.

Open the project →

Deterministic core

The whole simulation lives in pure Zig with no allocator in the per-frame hot path: the same seed and input stream always reproduce the same run, and every rule is covered by 68 headless unit tests.

Scripted levels

A strict line/brace .beam format declares the player, enemy defs, waves, bosses, and power-up drops. Tune levels as text; bad scripts fail with clear errors.

Procedural everything

Sprites, a 3x5 bitmap font, a seeded starfield, and a subtractive 12-voice synth are all generated in code. No assets, no external audio files.

Zig, first for the factory

The factory's first Zig project. SDL2 is the only dependency, and only the platform layer touches it; CI stays headless.

Try it

cd beambus
zig build            # debug build
zig build test       # 68 headless tests (no SDL needed)
zig build check      # headless self-checks
zig build run        # play in an SDL window

./zig-out/bin/beambus                  # play in a window (480x600 x2)
./zig-out/bin/beambus --headless       # simulate, print a summary
./zig-out/bin/beambus --self-check     # run invariant checks
./zig-out/bin/beambus --level levels/level1.beam
./zig-out/bin/beambus --seed 42        # fixed seed, deterministic replay

How it works

  • Entity pool. Player, enemies, player/enemy bullets, particles, power-up drops, and floating score text all live in one fixed-capacity (1024-slot) arena with an O(1) free list. Spawning never allocates; a cull pass returns dead entities. The loop is a single switch on entity kind.
  • Level script. name, background, player { ... }, enemy <name> { ... }, wave { ... }, boss { ... }, and powerup { ... } directives are parsed line by line. Waves spawn enemies one at a time on an interval; bosses and power-up drops enter on a timer; every reference to an enemy is validated at parse time.
  • Movement patterns. Each pattern is a small closed-form update: sine oscillates while falling, zigzag alternates direction, swoop arcs across, drift sways slowly, orbit is the boss sweep that holds altitude, and spiral combines cosine and sine motion.
  • Simulation loop. Each step advances time, updates the player from a normalized input snapshot, spawns waves and bosses, moves enemies by pattern, moves bullets, runs circle collisions, updates particles, and culls the pool. Determinism comes from the seeded SplitMix64 PRNG and the absence of allocation or SDL state in the hot path.
  • Weapon tiers. Touching a spread power-up raises the fire level from single to twin to triple spread (capped at 3). Dying resets the tier to single.
  • Enemy volleys. Enemy defs and bosses accept shots (bullets per trigger) and spread (fan angle in radians), so any enemy can throw a volley, from a two-shot burst to a wide five-way fan, without new code.
  • Shields. A shield drop equips a one-hit bubble that absorbs the next hit instead of costing a life, drawn as a ring around the ship.
  • Combo scoring. Consecutive kills without taking a hit build a score multiplier (x2 at 5, x3 at 10, capped at x4), shown next to the score. Any hit resets it.
  • Bonus lives. The player { life_every N } key awards an extra life each time the score crosses another N points.
  • Grazing. An enemy bullet that passes within a narrow band around the ship without hitting scores points scaled by the combo multiplier and rings a soft tick, rewarding close dodges. The HUD counts grazes.
  • Smart bombs. The player { bombs N } key starts the player with N bombs; detonating one (B/V) clears every enemy bullet on screen and deals two points of damage to every enemy, with kills scoring through the combo multiplier. A white flash and a dedicated sound sell the detonation; the HUD tracks the stock.
  • Respawn invulnerability. A fresh spawn gets a two-second invulnerability window (the ship blinks), so a bullet crossing the spawn point can never kill you instantly.
  • Renderer. Pure Zig over a u32 pixel buffer (0xAARRGGBB, ready for SDL_PIXELFORMAT_ARGB8888). Rect, circle, circle-stroke, and triangle primitives are hand-rolled; text uses a 3x5 bitmap glyph set; the starfield is seeded per run and scrolls downward.
  • Audio. A fixed 12-voice synth, each voice a wave (square, saw, noise) with frequency, slide, amplitude, and a TTL-shaped decay envelope. Shoot, hit, explosion, player-hit, power-up, shield-break, bonus-life, and bomb effects are layered voice stacks; output is deterministic and clamped to [-1, 1]. SDL is fed via SDL_QueueAudio (no callback, no threads).
  • CLI. A hand-rolled arg parser handles --level, --seed, --scale, --seconds, --headless, --self-check, --version, and --help; bad values produce a clear message and a non-zero exit.

Design choices

  • Zig, and headless-first. The core is deliberately SDL-free so every rule of the game is covered by 68 unit tests that run anywhere, with no window and no audio device.
  • No allocator in the hot path. The entity arena is fixed at compile time: deterministic, cache-friendly, and free of OOM states.
  • Deterministic by default. Windowed mode seeds from the clock unless --seed is given; headless and self-check modes use fixed seeds so replays are exact.
  • Scriptable levels. Levels are data, not code; the strict parser catches mistakes at load time.
  • Self-verifying. zig build check re-runs core invariants (bounded simulation, seed determinism, distinct-seed validity) at runtime, and zig build test covers every SDL-free module.

Level format

The .beam format has its own reference page: level-format.md. A short example:

name "The Drone Swarm"
background #0b0e14
player { speed 260 fire_rate 0.16 lives 3 life_every 10000 bombs 2 }
enemy grunt { hp 1 speed 90 points 100 radius 8 fire_rate 0.5 color #e8594f }
wave { at 2 kind grunt count 6 interval 0.4 pattern sine armed false }
boss { at 45 kind tank hp 80 speed 40 points 5000 fire_rate 0.8 color #ffd23f }
powerup { at 16 kind spread }
powerup { at 22 kind shield }
