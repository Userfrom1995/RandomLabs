Binding spec: `progress/286-sextant-research.md` section 4.
Implementation: `src/Sextant.Core/Geometry.cs`, `src/Sextant.Core/TileBuilder.cs`,
`src/Sextant.Core/Packs.cs`, `tools/Sextant.Pack/`.
Gates: `tests/Sextant.Core.Tests/TileBuilderTests.cs` (21 tests, green).

## Asset format

The client asset is newline-delimited GeoJSON, one file per layer
(`roads`, `buildings`, `water`, `landuse`, `pois`), WGS84 lon/lat, `\n`
newlines, UTF-8 no BOM, coordinates rounded to 7 decimals (~1 cm), features
sorted ordinally. Versioned under `src/Sextant.App/wwwroot/packs/v1/` with a
`pack.json` manifest (`sextant-pack/1`: version + seed + center + per-layer
counts + source; no timestamps, so bytes are reproducible).

The v1 sample pack is fully synthetic (grid streets, inset building rects, a
river band, a park, 12 named POIs around downtown Portland), generated by
`Sextant.Pack <out-pack-dir>` with seed 286: 140 features, license-light, no
ODbL attribution needed. OSM-derived extracts may replace it later; they must
add the attribution chip plus a `docs/ATTRIBUTION.md` entry.

## Runtime tile

`TileBuilder.BuildTile(z, x, y, inputs, tolOverride?)` computes one tile in
memory per (z, x, y). Per feature: clip to the tile lon/lat rect, simplify at
the zoom tolerance, quantize to 4096 extents, drop degenerates. (Feature
pre-selection moves into an R-tree window query in Phase 3; the clip here
stays as the exact edge cutter.) Output features are sorted by
(layer, kind, coordinates), so the same input bytes always yield the same
canonical bytes (`TileCanonical.Serialize`); the determinism gate builds twice
(including reversed input order) and asserts byte equality, and the packer is
verified byte-identical across runs (`diff -r`).

## Clip

- Polygon rings: Sutherland-Hodgman against the four tile half-planes.
- Polylines: Liang-Barsky per segment, stitching consecutive pieces that share
  an endpoint (a line dipping in and out yields several pieces).
- Points: inclusive tile containment test.
- Golden: an oversized ring clips to exactly the 4 tile corners; a diameter
  crossing yields one 2-point piece on the tile edges; a dip yields two pieces.

## Simplify

Radial-distance pre-pass plus Douglas-Peucker (the simplify-js combination),
in WGS84 degrees. Extent-unit budgets per zoom (research 4.2):

| zoom | tol (extents) | tol at z14 (deg) |
|------|---------------|------------------|
| <= 10 | 8 | - |
| 11-13 | 4 | - |
| >= 14 | 1.5 | ~8.1e-6 (~0.9 m) |

Conversion: `tolDeg = tolExtents / 4096 * (360 / 2^z)`. Endpoints are never
dropped. Gates: sub-tolerance waviness collapses to endpoints; zigzag
deviation stays within tolerance; Hausdorff deviation at z14 is under 0.5 px
(8 extents, measured far below); a collinear 101-point line collapses to 2.

## Quantize

Linear map of the tile rect onto `[0, 4096]`, y flipped (north = 0),
MVT-compatible convention. No protobuf wire in v1: producer and consumer are
both Sextant, so a future MVT decoder slots in without changing the pipeline.
Gates: corners map to `(0,0)`/`(4096,4096)`, center to `(2048,2048)`;
roundtrip within half an extent (1000 seeded points); overzoom identity (a
ground point quantized in the z14 parent and the z15 child dequantize to the
same lon/lat within the child half-extent; scale `2^(15-14) = 2`).

## Reprojection

`Reprojector.ReprojectTo(input, dst)` carries a whole WGS84 tile input into
the destination projection (the Phase 5 Albers view path: WGS84 stays the
source of truth, projected vertices are per-projection cache generations).
Out-of-domain points are dropped; a feature left with no valid geometry
returns null. Projected meters ride in the `GeoPoint` fields so the pipeline
shape stays uniform; the caller renders them as planar meters.
