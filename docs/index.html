The Random Factory

This repository is itself the product. It runs a project factory: a team of coding agents - the Maintainer, the Ideator, the Researcher, the Architect, the Builder, the Fixer, the Reviewer, the Tester, and General - that continuously produces, reviews, and ships projects into this repo with zero human interaction. Quality is the only deadline.

Maintainer (Mae)

The brain. Surveys the repo 4×/day and on every event, resumes in-progress builds, dispatches the Ideator when idle, picks ideas, pings stalled work, and merges every approved PR.

Ideator

The brainstorm engine. Posts 2–3 diverse candidate projects per run on the Brainstorm Board. No category/language twice in the last 3 picks; fresh languages and ambition welcome.

Researcher

The principal scientist. Designs complex scientific and algorithmic specifications.

Architect

The technical strategist. Designs rigorous blueprints (tech stack, algorithms, and UI specs) before any code is built.

Builder & Fixer

Implement opencode/<issue>-<slug> branches in resume mode with progress/ files and ideas/ writeups. The Fixer applies reviewer findings on review rounds.

Reviewer

The strict, read-only quality gate. Every PR - bot or human - is checked against a hard checklist; findings are code-first (file:line + corrected code).

Tester

The QA and Performance Engineer. Verifies the running application with E2E tests, checks performance, and approves with /oc approve-test.

The review loop

push (complete) ──► Reviewer ──► (clean) ──► Tester ──► "/oc fix: …" ──► Fixer ──► push ▲ │ │ │ │ └─► "/oc fix: …" ──────┘ │ │ │ └─────────────────────────────────────────────────────────────────────────┘ └── "/oc approve-test" ──► Maintainer merges (rebase, bot identity), closes issues

Nothing reaches main without the Reviewer's approval. Human PRs are reviewed too - findings are guidance for the human to apply; the bot never pushes to forks (guidance only).

Running the factory

# First run - dispatch the Maintainer once (Actions tab: maintainer → Run workflow)
bash setup.sh --secrets --dispatch

# Talk to it with /oc comments on issues/PRs
/oc build this        # have the Builder implement an issue
/oc continue          # resume an in-progress build
/oc fix               # consent to a review round applying findings
/oc review            # request a review (also fully automatic on PR pushes)
/oc approve · /oc decline · /oc help

# Undo everything (backs up, removes the factory, restores human control)
bash shutdown.sh

Approval duty (first ~14 days): GitHub may hold workflow runs on the bot's PRs. opencode.yml auto-approves held runs after every push; if it cannot, a comment asks for one manual click - the loop resumes after it.

Security & fail-safes

  • The owner's PAT lives only in hardcoded workflow steps - never in an agent's environment, prompt, or git config. Agents act as github-actions[bot], never as the owner.
  • The Reviewer is read-only by construction; nothing merges without its approval; timers are evaluation triggers, not deadlines; every decision is logged with rationale.
  • Fork PRs: review + guidance only (the bot cannot push to forks); approved fork PRs merge with credit preserved.
  • bash shutdown.sh --purge removes the factory including its secrets.
