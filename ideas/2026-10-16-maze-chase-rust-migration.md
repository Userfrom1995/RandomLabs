# Maze-Chase Rust Migration - Architectural Blueprint

- **Issue:** #582 (parent tracker; gameplay reference #552 stays functional until replacement is verified)
- **Date:** 2026-10-16
- **Track:** Product (End-User Application, three publication layers on one engine)
- **Stack:** Rust stable (2021 edition+), Cargo workspace; engine with zero platform deps; desktop via macroquad/miniquad (eframe fallback); terminal via ratatui plus crossterm plus ratatui-image with Unicode fallback; WASM via miniquad same-renderer build plus wasm-bindgen and web-sys shims; audio via engine trait with rodio native impl, web-audio WASM shim, null impl for CI
- **Clean-room rule (binding):** original code, original names, original mazes, original art, original audio, original branding only. Mechanics are reimplemented from behavioral descriptions and legitimate public sources, never pasted from proprietary source, ROMs, ripped sprites, or copied timing tables. The Python #552 game is empirical input (ghost timing feel, renderer tiers, layout engine, verify-matrix practice), not code to port line by line.

## Summary

Rebuild the maze-chase game as a complete, original, production-quality Rust project: one central deterministic engine (core logic, state, collision, movement, ghost behavior, scoring, levels, progression) plus three fully functional publication layers on the same engine. Native desktop apps for Windows, macOS, and Linux with proper packaging and polished GUI. A polished terminal game with intelligent space use, dynamic resize, Kitty and Ghostty capability use plus conventional-terminal fallback, distributable package, and launch command. A complete browser-playable WebAssembly build on GitHub Pages with keyboard and touch controls, polished on desktop and mobile. No secondary-demo layers: every layer is a complete product. Platform differences are limited to controls, presentation, and genuine capability gaps, and every gap is investigated and documented, never silently dropped. A shared feature-completeness matrix tracks every mechanic through implementation and testing on all three layers.

## Why

Python #552 proved the gameplay shape and the verification discipline (headless matrices, true-pty tours, scoreboards), but one language cannot ship all three publication targets well. Rust gives a single memory-safe engine with deterministic fixed-point friendly simulation, plus native binaries for every desktop OS, plus a real terminal story (ratatui plus crossterm is the maintained standard), plus a browser story (miniquad compiles the same renderer to WASM) without triple-maintaining gameplay logic. The workspace split (pure engine, thin adapters) is what makes "no triple-maintained gameplay logic" enforceable: layers map input to `TickInput` and render `Game` state plus `GameEvent`s, and nothing else. Clean-room reimplementation removes proprietary-asset risk while keeping the mechanics players expect from the genre.

## How It Works

The engine owns the truth. A fixed-timestep accumulator advances the simulation at 120 ticks per second in discrete integer-friendly steps: read buffered directional intent, apply tile-center movement with cornering assist, advance the scatter and chase wave clock (with reversals), advance fright timers, step each ghost (target selection by personality and mode, greedy non-reversing exit choice at intersections, house exit counters plus idle timeout, tunnel clamp, late-level pursuer stages), resolve pellet, energizer, bonus-item, and collision events, emit `GameEvent`s for score and audio and UI. Actor speeds, fright curves, spawn thresholds, scoring chains, and level ramp tables live in one `tuning` module with provenance comments (authored values inspired by public behavioral analyses, never copied tables). Determinism comes from a seeded PRNG with subsystem stream splits (ghost RNG vs bonus RNG) so visual-only changes never alter simulation hashes, plus a replay log (input list plus seed) and a canonical state hash used by tests and the verify harness.

Each publication layer is a thin adapter over the same engine. The terminal layer owns the cell grid, layout regions, capability probing, and escape-sequence emit; it never recomputes collisions or ghost targets. The desktop layer owns the window, sprite batch renderer, input mapping (keyboard plus gamepad), audio routing, and OS packaging; it renders engine state at display rate while the sim stays fixed-step. The WASM layer owns the canvas renderer (same macroquad/miniquad draw code as desktop behind a target flag), keyboard plus touch mapping to the same `TickInput`, DPR-aware resize, and the web-audio shim. Shared `assets` and `config` crates load original PNG/OGG/WAV, authored level files, themes, keymaps, and persisted settings once; layers only scale, blit, transcode, or present. Anything a layer cannot do (for example, image protocols on a dumb terminal) degrades through a documented path with a matrix entry, never a silent drop.

## Module Breakdown (one coherent system)

## Key Data Structures and Algorithms

- Maze: compact byte grid (wall, corridor, pellet bitmask parallel array), neighbor lookup O(1), flood-fill O(cells) at load for reachability; eyes pathing uses bounded BFS on the tiny grid; ghost steering uses greedy Euclidean exit choice O(degree) at intersections with fixed tie-breaks.
- Frame model: engine exposes a tile query API; terminal frame buffer is a cols-by-rows cell array with dirty-set tracking, diff emit O(dirty) per frame; desktop/WASM sprite batches are rebuilt from engine state each frame, O(actors plus dirty tiles).
- Ghost targeting: pure functions `target(ghost, game) -> tile`; personalities are Leader (player tile), Ambusher (tiles ahead of mouth), Flanker (pivot vector off Leader), Lurker (distance-switched chase/retreat). Scatter corners are four authored fixed targets. Frightened uses seeded RNG turns. All tables in `tuning.rs` are authored originals with provenance comments.
- Determinism: seeded generator streams split by subsystem; canonical hash covers maze, actors, ghosts, score, level, timers; replay file (seed plus inputs) reproduces any run bit-exactly for tests and bug reports.

## Testing Strategy

- Unit plus headless: Rust test suites for engine determinism, wave tables, fright chains, bonus spawn/expire, house counters, pursuer triggers, tunnel wrap, collision priority, config validation. Golden replay hashes pinned per seed.
- Escape-sequence capture: terminal backends return strings into buffers in tests; assert Kitty transmit-once then place, Sixel framing, Unicode diff minimality; determinism of payloads under pinned encoders.
- Live verification: `verify` matrix (gameplay plus size plus capability plus input plus parity rows) runs headless against the real code in CI; true-terminal tours (Kitty, Ghostty where runners provide them, otherwise capture) cover title, gameplay, pause, too-small, teardown; per-OS runners (Linux, macOS, Windows) cover input methods, audio fallback paths, resize, and backend selection; Playwright covers WASM keyboard and touch on desktop and mobile viewports.
- Benchmarks: bench harness records FPS per backend and layer, input latency, encode time, and auto-degrade events into `scoreboard.md`; regressions against the published floor are blocking.
- Baseline parity: the behavior checklist (personalities, waves, fright, bonus, scoring, tunnel, counters, pursuer stages) is verified against the #552 reference behavior spec in this blueprint, never against any copied artifact; each checklist item names its test file and seed.
- Release bar: automated engine and gameplay tests plus integration and E2E per layer; release ships desktop packages, terminal package plus launch docs, WASM deploy, original assets and audio and docs, reproducible build and release instructions, matrix and test results. Complete means implemented, tested, and verified against acceptance criteria.

## Risks and Mitigations

- WASM audio autoplay policies: start muted or on first gesture, web-audio unlock on tap or keypress, null-audio fallback logged honestly.
- Terminal image throughput (Ghostty, tmux, SSH): small atlas, placements over retransmits, watchdog degrades to Unicode rather than stuttering; tmux and SSH paths documented with honest capability notes.
- Sixel re-encode cost: frame cap, Unicode recommendation on weak machines, documented tradeoff.
- Windows input and audio divergence: single input abstraction with per-OS readers, rodio routing per OS, matrix CI on all three runners.
- Scope creep into triple-maintained logic: enforced by the pure-engine boundary plus a review rule (any gameplay branch in a layer crate is a blocking finding) plus the matrix (every mechanic names its engine module).
- Legal residual risk: replacing assets alone is not assumed to remove all risk; `legal.md` logs sources, naming rationale, maze-geometry authorship, and anything needing legal review; near-identical maze geometry, lookalike sprites or sounds, cloned data tables, and trademarked terms are flagged, never shipped on assumption.

## Evolution Notes

- The architecture supports future add-ons (netplay spectator, level editor, native-audio expansion) without engine breakage because the engine is pure and the adapter interfaces are tick-in plus events-out. Those are options, not commitments; no stub flags or menu entries anticipate them.
