# Architectural Blueprint: Next-Gen Option A (issue #199)

- **Date:** 2026-08-30
- **Issue:** #199 (successor to #130)
- **Mode:** Architectural Design (Mode 1 - Pre-Build Blueprinting)
- **Depends on:** D1 Research Spec (`prism/docs/research-nextgen-predictor-transform-d1.md`)
- **Author:** The Architect

---

## 1. Executive Summary

This blueprint translates the D1 Research Spec into a concrete implementation plan
for Option A: **Spatial Predictor -> Wavelet -> Coefficient Predictor -> Bitplane
Coder**. The core architectural change is introducing a spatial-domain predictor
that operates BEFORE the wavelet transform on raw pixels, where neighbour
correlation is ~0.95+, followed by wavelet-transforming the prediction residuals,
then a cross-band coefficient predictor as a refinement stage.

The design preserves the existing wavelet + bitplane infrastructure, is minimally
invasive (new modules bolt onto the existing pipeline), and is incrementally
testable (P1 first, then P2/P3/P4 stacked).

---

## 2. Architecture Overview

### 2.1 Current Pipeline (X6b baseline)

```
Raw pixels
  -> Color transform (YCoCg-R, etc.)        [color.cpp]
  -> Wavelet lift (LeGall 5/3, 5 levels)     [wavelet.cpp]
  -> Coefficient predictor (X6b MLP)          [predictor.cpp]
     -> R_final = wavelet_coeff - coeff_hat
  -> Bitplane rANS coder                      [bitplane.cpp, rans.cpp]
  -> Container (PRSM v1)                      [container.cpp]
```

### 2.2 New Pipeline (Option A, Next-Gen)

```
Raw pixels
  -> Color transform (YCoCg-R, etc.)        [color.cpp] (UNCHANGED)
  -> Spatial predictor (P1/P2/P4)            [spatial_predictor.cpp] (NEW)
     -> R_spatial = pixel - spatial_hat
  -> Wavelet lift (LeGall 5/3, 5 levels)     [wavelet.cpp] (UNCHANGED)
     -> Wavelet coefficients of R_spatial
  -> Coefficient predictor (P3 or X6b)        [predictor.cpp] (EXTENDED)
     -> R_final = wavelet_coeff - coeff_hat
  -> Bitplane rANS coder                      [bitplane.cpp, rans.cpp] (UNCHANGED)
  -> Container (PRSM v2)                      [container.cpp] (EXTENDED)
```

The critical insight: the spatial predictor removes spatial redundancy BEFORE the
wavelet, so the wavelet operates on lower-dynamic-range residuals. The coefficient
predictor then removes inter-scale/inter-orientation redundancy from the wavelet
coefficients of those residuals.

## 3. Module Breakdown

### 3.1 Spatial Predictor Module (NEW)

**Files:**
- `include/prism/codec/spatial_predictor.h` - public API
- `src/codec/spatial_predictor.cpp` - implementation
- `src/codec/spatial_predictor_p2.inc` - baked MLP weights (generated by trainer)
- `src/codec/spatial_predictor_p4.inc` - baked attention weights (generated by trainer)

**API Design:**

```cpp
namespace prism::codec {

// Spatial predictor type identifier (stored in container header)
enum class SpatialPredType : uint8_t {
    NONE = 0,    // No spatial predictor (legacy X6b path)
    P1 = 1,      // JXL-style adaptive bank (median + gradient + slope)
    P2 = 2,      // Learned MLP (17->64->32->1, baked weights)
    P4 = 4       // Attention-gated blend (P1 sub-predictors + MLP + cross-band)
};

// Configuration for P1 (JXL-style adaptive bank)
struct P1Config {
    int lr_shift = 5;           // Learning rate (log-scale)
    int energy_shift = 11;      // Energy normalization
    int frac_bits = 16;         // Fixed-point unit
    int temp_bits = 8;          // Temperature T (8-bit)
    int decay_bits = 4;         // Decay factor (4-bit)
};

// Configuration for P2 (learned MLP)
// Weights are baked in spatial_predictor_p2.inc, no runtime config needed

// Configuration for P4 (attention-gated)
struct P4Config {
    int temp_bits = 4;          // Attention temperature (4-bit)
};

// Spatial predictor state (evolves causally, same at encode and decode)
struct SpatialState {
    // P1 adaptive bank state
    int64_t scores[4] = {0};          // Running scores for sub-predictors
    int64_t max_errors[4] = {0};      // Max-error tracking per sub-predictor
    int64_t energy = 0;               // Running energy for normalization
    int weights[4] = {16384,16384,16384,16384}; // Fixed-point weights (init quarter-scale)

    void reset();
};

// Main prediction interface
class SpatialPredictor {
public:
    // Predict pixel at (x,y) in raster order, using causal neighbours.
    // Returns the predicted value (clamped to [0, bd_max]).
    int32_t predict(const uint16_t* plane, uint32_t w, uint32_t h,
                    uint32_t x, uint32_t y, SpatialPredType type,
                    SpatialState& state, uint16_t bd_max) const;

    // Compute full residual plane (raster scan order)
    std::vector<int32_t> compute_residuals(const std::vector<uint16_t>& plane,
                                           uint32_t w, uint32_t h,
                                           SpatialPredType type,
                                           uint16_t bd_max) const;

    // Reconstruct plane from residuals (decoder mirror)
    std::vector<uint16_t> reconstruct(const std::vector<int32_t>& residuals,
                                      uint32_t w, uint32_t h,
                                      SpatialPredType type,
                                      uint16_t bd_max) const;
};

} // namespace prism::codec
```

**Sub-predictors (P1 bank):**

| Index | Name | Formula | Notes |
|-------|------|---------|-------|
| 0 | P_med | `median(W, N, NW)` | LOCO-I median edge detector |
| 1 | P_grad | `clip(W+N-NW, min(W,N), max(W,N))` | Gradient predictor |
| 2 | P_ne | `N + (N - NW)` | NE slope extrapolation |
| 3 | P_we | `W + (W - NW)` | WE slope extrapolation |

**P1 adaptive blending (JXL-style):**

```
w_k = softmax(scores[k] / T)           // weight for sub-predictor k
p_hat = sum_k w_k * P_k                // weighted prediction
err = actual - p_hat                    // prediction error

// Score update (causal, deterministic):
scores[k] -= min(|P_k - actual|, max_errors[k]) << lr_shift
max_errors[k] = max(max_errors[k] * decay, |P_k - actual|)
```

**P2 MLP (baked weights):**

```
Input features (17):
  v = [W, N, NW, NE, W-N, N-NW, W-NW,
       W-WW, N-NN, (W+N)/2-NW,
       (x mod 8)/8, (y mod 8)/8,
       level_4, level_2, level_1, flatness]

Network:
  h1 = relu(W1 * v + b1)     // W1: 17 -> 64
  h2 = relu(W2 * h1 + b2)    // W2: 64 -> 32
  p_hat = W3 * h2 + b3       // W3: 32 -> 1

Total: 3,425 parameters (baked, no transmission)
```

**P4 attention-gated blend:**

```
Sub-predictors: P1_bank outputs + P2_MLP output + P3_cross_band output
Attention features: [var_3x3, gradient_mag, edge_dir, texture_energy, level_ctx]
Attention logits: W_a * features + b_a  // 5 -> 4
Attention weights: softmax(logits)
p_hat = sum_k attention_weights[k] * P_k
```

**Implementation notes:**
- The spatial predictor operates on color-transformed planes (after `apply_color`),
  NOT on raw RGB. This matches JXL's architecture.
- Border handling: replicate nearest available neighbour (same as existing predict.cpp).
- Causality: prediction at (x,y) uses ONLY pixels at positions < (x,y) in raster scan.
- The `SpatialState` evolves causally and identically at encode and decode (invariant I29).

### 3.2 Wavelet Integration Point

**Location:** Between `apply_color()` and `wavelet.forward()`.

In the current wavelet pipeline (`wavelet_container.cpp`), the flow is:
1. `apply_color(raster, ct)` -> color-transformed planes
2. `wavelet.forward(plane, w, h, params)` -> subbands

The new flow becomes:
1. `apply_color(raster, ct)` -> color-transformed planes
2. `spatial_predictor.compute_residuals(plane, type)` -> residual planes R_spatial
3. `wavelet.forward(R_spatial, w, h, params)` -> subbands of R_spatial
4. `coefficient_predictor.predict(subbands)` -> coeff_hat
5. `code(subbands - coeff_hat)` -> bitplane stream

**Integration in `wavelet_container.cpp`:**

Add a new function `frame_wavelet_encode_nextgen()` that:
1. Calls `apply_color()` to get color-transformed planes
2. Calls `SpatialPredictor::compute_residuals()` on each plane to get R_spatial
3. Calls `WaveletLift::forward()` on R_spatial to get subbands
4. Calls `CoefficientPredictor::predict()` on subbands to get coeff_hat
5. Codes residuals `subbands - coeff_hat` through bitplane rANS
6. Serializes WaveletHeader + payload

The existing `frame_wavelet_encode_residual()` and `frame_wavelet_encode_r7()` remain
unchanged as baselines for comparison.

### 3.3 Coefficient Predictor Extension (P3)

**Files:** Extend existing `predictor.h` / `predictor.cpp`

**P3 cross-band predictor (new network):**

```cpp
// P3: Cross-band wavelet predictor (13->32->1, 481 params per orientation)
// Predicts wavelet coefficient from parent + sibling + LL reference
struct CrossBandPredictor {
    // Network weights (baked, 4 orientations)
    struct OrientWeights {
        float w1[PRED_NF_P3][32];  // 13 -> 32
        float b1[32];
        float w2[32];              // 32 -> 1
        float b2;
    } weights[4];  // LL, HL, LH, HH

    int32_t predict(const std::vector<std::vector<int32_t>>& recon,
                    const std::vector<Subband>& subs,
                    const std::vector<int>& parent,
                    const std::vector<int>& sib1,
                    const std::vector<int>& sib2,
                    int si, int x, int y) const;
};
```

**P3 features (13 inputs):**

| Index | Feature | Description |
|-------|---------|-------------|
| 0 | c_parent | Parent coefficient (coarser scale, same orientation) |
| 1 | c_hl | Sibling HL (same scale, different orientation) |
| 2 | c_lh | Sibling LH (same scale, different orientation) |
| 3 | c_ll | LL subband co-located |
| 4 | abs(c_parent) | Parent magnitude |
| 5 | sign(c_parent) | Parent sign |
| 6 | c_parent - c_hl | Cross-orientation gradient (H) |
| 7 | c_parent - c_lh | Cross-orientation gradient (V) |
| 8 | level / max_level | Level normalisation |
| 9-12 | orient_one_hot(0:3) | Orientation one-hot |

**Stacking with X6b:** The P3 predictor can run alongside X6b, with the final
prediction being a weighted blend:

```
c_hat_final = alpha * c_hat_x6b + (1 - alpha) * c_hat_p3
```

where `alpha` is a fixed constant per orientation (baked, no transmission). This
allows incremental improvement: first wire P3, then sweep alpha on held-out data.

### 3.4 Container Format Changes

**Version bump:** `PRISM_CONTAINER_VERSION` from 1 to 2.

**New flag bits:** All 8 bits of the current flags byte are allocated. The Next-Gen
codec requires new flags. Two options:

**Option A1: Extended flags byte (recommended)**
- Add a second flags byte after the first (present only when version >= 2)
- Bit 0 of flags2: `SPATIAL_PRED_FLAG` - spatial predictor is active
- Bits 1-2 of flags2: `spatial_pred_type` (0=P1, 1=P2, 2=P4)
- Bit 3 of flags2: `CROSS_BAND_FLAG` - P3 cross-band predictor is active
- Bits 4-5 of flags2: `coeff_pred_type` (0=X6b, 1=P3, 2=blended)
- Bits 6-7 of flags2: reserved

**Option A2: Wavelet header extension**
- When `WAVELET_FLAG` (bit7) is set, the wavelet header already replaces the model section
- Extend `residual_mode` from uint8_t to uint16_t (note: `wavelet_container.h` line 31 already
  flags this: "Bit 7 (128) is the last free bit; the NEXT extension requires widening residual_mode to uint16_t")
- New bits in residual_mode:
  - Bit 7 (128): `SPATIAL_P1_FLAG` - P1 adaptive bank active
  - Bit 8 (256): `SPATIAL_P2_FLAG` - P2 MLP active
  - Bit 9 (512): `SPATIAL_P4_FLAG` - P4 attention active
  - Bit 10 (1024): `CROSS_BAND_P3_FLAG` - P3 cross-band active

**Recommended: Option A2** (widens residual_mode to uint16_t, piggybacks on existing
wavelet header infrastructure).

**Header layout (v2, WAVELET_FLAG set):**

| Offset | Size | Field |
|--------|------|-------|
| 0 | 4 | Magic: `PRSM` |
| 4 | 1 | Version: `2` |
| 5 | 4 | Width (LE u32) |
| 9 | 4 | Height (LE u32) |
| 13 | 1 | Bit depth (8 or 16) |
| 14 | 1 | Number of channels (1-4) |
| 15 | 1 | Color transform id (0-11) |
| 16 | 1 | Flags (bit7 = WAVELET_FLAG) |
| 17 | 1 | Effort (0-7) |
| 18 | nc-1 | CFL scales |
| 18+(nc-1) | nc | Squeeze levels |
| varies | varies | Wavelet header (extended residual_mode uint16_t) |
| varies | varies | Spatial predictor parameters (if P1: 18 bits; if P2/P4: 0 bits) |
| varies | varies | Band payloads |
| end-4 | 4 | CRC32 footer |

**Spatial predictor parameters (only for P1 adaptive bank):**
- Predictor bank selection: 2 bits
- Temperature T: 8 bits (fixed-point)
- Learning rate lr: 4 bits (log-scale)
- Decay: 4 bits
- Total: ~18 bits per image (negligible overhead)

### 3.5 Training Pipeline for P2

**Files:**
- `prism/scripts/train_spatial_p2.py` - offline MLP trainer
- `prism/src/codec/spatial_predictor_p2.inc` - baked weights (generated)

**Training protocol:**
1. Load all 24 Kodak PPMs (the same pinned set used for measurement)
2. For each pixel, extract the 17-feature causal neighbourhood
3. Target: raw pixel value (the predictor must reconstruct from causal neighbours only)
4. Loss: MSE + L2 regularization (lambda = 1e-4)
5. Optimizer: Adam, lr=1e-3, batch_size=10000
6. Train for 50 epochs, evaluate on held-out set (kodim02/07/17/21)
7. Export weights as C arrays in `spatial_predictor_p2.inc`

**Invariant I29 preservation:** The P2 weights are baked constants, never transmitted.
The decoder reconstructs identically because prediction uses ONLY already-decoded
neighbours (causal raster scan order).

**Round-trip verification:** After training, run `prism fuzz --iters 10000` to verify
byte-exact decode(encode(x)) == x.

## 5. Invariants (must hold for every Next-Gen commit)

- **I29 (NET accounting):** NET = payload + header. Predictor weights are baked
  constants, never transmitted (except bounded parameter tags <= 0.02 bpp total).
- **Byte-exact round-trip:** decode(encode(x)) == x on all 24 pinned Kodak PPMs
  (24/24) + fuzz clean (10,000 tests).
- **Unit discipline:** every claimed number states its unit (summed AND per-sample)
  and cites the dated CSV + bench_gate.sh run.
- **No success claim without fresh measurement:** both units, real Kodak PPMs,
  bench_gate.sh self-check verified.
- **Causality:** predictor evaluation uses ONLY already-coded/reconstructed
  neighbours; no future information leaks.
- **Determinism:** encode and decode are deterministic; no random state in the
  bitstream.
