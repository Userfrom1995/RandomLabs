# Doom: client-side Web Doom engine at `/doom/` (architectural blueprint)

Date: 2026-09-17. Issue: #362. Research input: `doom/docs/research-spec.md` (binding: doomgeneric MVP plus Chocolate v1.1 plus Woof stretch, single-threaded Wasm, paletted WebGL upload with 7.6ms frame budget, DMX SFX plus Wasm OPL3 music, OPFS/IDB/localStorage ladder, 35Hz ticcmd controls, TTFF bands, baseline catalog, statistical gates) and `lab/memory/researcher/doom-362-notes.md` (Pages Wasm constraints bank). This blueprint resolves all five open risks from research spec section 10 (SDL2 vs shim, SIMD/scalar split, node-builder inclusion, Hexen dialect, multiplayer scope).

## Summary

Doom is a static-only browser Doom hosted at `/doom/index.html` (GitHub Pages, zero server runtime, zero runtime CDN, same-origin assets only, offline-capable after first load). A single-threaded C engine (doomgeneric shim for the MVP, Chocolate Doom 3.1.1 via the Emscripten SDL2 port for v1.1 behind the same JS/Wasm boundary) renders an 8-bit software framebuffer in Wasm linear memory; JS uploads it zero-copy as a paletted texture to a fullscreen WebGL quad (64 KB/frame at 320x200) with a Canvas2D plus pure-JS fallback ladder. Shareware DOOM1.WAD ships precached for instant play; user IWADs/PWADs load via drag-drop plus picker with layered corrupt-WAD errors. Audio is WebAudio DMX SFX (8-voice pool) plus MUS-to-MIDI conversion into a Wasm OPL3 FM worklet. Persistence is a `StorageProvider` interface (OPFS primary, IndexedDB secondary, localStorage config-only) with an export/import bundle. Controls sample into a 35 Hz `ticcmd` stream decoupled from the 60 Hz rAF loop, with Pointer Lock desktop plus a DOM touch overlay plus versioned remapping.

## Why

Emulation (js-dos/DOSBox, 10-50x overhead, jittery input, fragile PWAD story) and pure-JS rewrites (no demo parity, dead maintenance) cannot hit native 60 FPS with authentic behavior. GZDoom-class ports need pthreads plus SharedArrayBuffer plus COOP/COEP headers that Pages cannot set, plus 10-20 MB payloads. The chosen path (doomgeneric five-function shim now, Chocolate SDL2 later, Woof stretch) is the smallest proven Emscripten target (300-600 KB Wasm) with bug-for-bug vanilla lineage available when demo and save compatibility matter. The risk is not a novel algorithm but integration drift across dozens of small decisions (node formats, texture composition order, MUS controller mapping, tick timing, fallback ladders); this blueprint pins exactly one correct behavior per case so the Builder never guesses.

## How It Works

1. Boot: `app.js` probes capabilities (WebGL2 vs WebGL1 vs none, Wasm compile, SIMD128 via `WebAssembly.validate` on a test module), resolves a render tier (cached with manual override), loads the SIMD or scalar Wasm binary, fetches the shareware WAD from Cache Storage (network first visit, precached after), parses header plus directory plus E1M1, and starts the loop. Cold TTFF is reported banded (broadband 0.8-2.0s, solid 4G 2.5-5s, weak 4G 5-9s, warm 0.5-1.0s), never as a point value.
2. WAD ingest: one checked `DataView` reader (explicit little-endian reads, truncation throws, allocation caps from header counts). Header validates magic plus `numlumps` plus `infotableofs`; directory validates ranges (marker `size == 0` filepos never dereferenced). Map discovery scans for `^E[1-5]M[1-9]$` or `^MAP\d\d$` then checks the fixed 10-lump order (plus optional `BEHAVIOR`). PWADs apply last-wins by lump name with map-lump group replacement. Corrupt files resolve through the layered taxonomy (`E_CONTAINER` fatal file reject, `E_MAP` fatal per map, `E_REF` droppable map with message, `W_GEOM`/`W_MEDIA` warning plus fallback asset); one bad PWAD map never kills the load.
3. Frame: rAF driver plus 35 Hz fixed-step accumulator (`step = 28.571ms`, `acc += min(dt,100ms)`, cap 3 covering 85.7ms hitches, render every frame with `alpha = acc/step`). Input listeners only set flags plus a mouse-delta accumulator; each tick consumes them once into a `ticcmd` (deterministic, demo-compatible). Camera and sprite positions interpolate by alpha; simulation state never interpolates. The Wasm rasterizer draws into the exported 8-bit buffer; JS holds a `Uint8Array` view over `memory.buffer` (rebound on `memory.grow`, never sliced) and calls `texSubImage2D` zero-copy; one fullscreen `NEAREST` quad does palette lookup plus colormap/light plus damage flash plus gamma plus pillarbox. Budgets: tick 0.3ms amortized, rasterizer 3.0ms, upload 2.5ms max (paletted typically 0.3-0.8ms), shader plus composite 1.0ms, input/audio/overlay 0.8ms, total about 7.6ms of 16.667ms. Resolution ladder (640x400, 480x300, 320x200, 256x160 emergency) switches at most every 500ms on EWMA frame time.
4. Audio: `wadAudio` (pure DMX parse: `format == 3`, strip 2x16 pad bytes, u8 to f32) and `mus2mid` (pure Crispy single-track port, MUS 140 Hz deltas, scale-not-clamp volumes above 127, golden-tested) run headless first. SFX decodes lazily into an LRU cache and plays through an 8-voice pool (`GainNode` per voice into `StereoPannerNode` into the SFX bus: volume 0-127, separation swing 96, pitch `pitch/128` with deterministic-PRNG jitter, distance full inside 200 units falling to zero at 1200, MAP08 floor 15). Music converts MUS to SMF Type 0 then feeds a Wasm OPL3 FM worklet (Nuked core at 49716 Hz heritage, GENMIDI bank, loop flag, song switch on map change; pure-JS DBOPL fallback if Wasm is blocked). Mixer (master plus SFX plus music buses into a compressor) mutes click-free via `setTargetAtTime`; context creation and resume happen only inside a user gesture with an autoplay-policy probe and overlay.
5. Persistence: all state flows through `StorageProvider` (OPFS primary with tmp-write plus flush plus copy atomicity and debounced 500ms writes flushed on `visibilitychange`/`pagehide`; IndexedDB `doom-store` secondary; localStorage config-only last resort). Savegames stay opaque bytes end to end; config, bindings, and progression are small JSON synced on change. Export builds a versioned JSON plus base64 bundle (`doom-save-bundle` v1) as a Blob download; import validates format plus version and applies atomically or rejects whole.
6. Input: desktop uses `e.code` arrows plus WASD with Pointer Lock (`unadjustedMovement` with bare-call fallback, ESC auto-pause plus click-to-recapture overlay, drag fallback on error). Touch is a DOM overlay (Pointer Events, per-`pointerId`, 44px targets, dynamic-origin joystick, FIRE/USE/strafe/weapon strip/menu, coarse-pointer only, 390px portrait bottom-sheet vs landscape translucent overlay, safe-area insets, throttled haptics). Remapping captures the next `keydown`, offers conflict swap, persists versioned `doom-bindings` v1. Full keyboard-only and screen-reader paths (focus trap, `aria-live` status, reduced-motion disables bob/shake/flash).

## Module Breakdown (domain decoupled from presentation)

Domain (headless, no DOM; unit-testable in Node/vitest):

- `doom/src/wad/`: `checkedReader.js` (LE-only throwing reader), `wadDir.js` (header plus directory), `mapDiscovery.js` (marker regex plus order check, partial-PWAD flag), `lumpDecoders.js` (vertices 4B, things 10/20B, linedefs 14/16B, sidedefs 30B, sectors 26B, segs 12B, subsectors 4B, nodes 28B, reject, blockmap with 16-bit vs 32-bit heuristic), `extNodes.js` (vanilla first, then XNOD/ZNOD/XGLN family with capped inflate, then glBSP `GL_*` V1-V5, DeePBSP V4 lowest), `textures.js` (PNAMES, TEXTURE1/2 with TEXTURE2 override, `R_GenerateTexture` order blit, flats 4096B, picture column-post bounded reader, PLAYPAL 10752B, COLORMAP 8704B), `hexenDetect.js` (BEHAVIOR present means detect-and-report v1 message), `errors.js` (`{code,lump,map,offset,expected,actual,severity,fallback}` plus per-map report), `demos.js` (version byte gate 109, header plus tic count, no simulation), `dehacked.js` (surface bytes plus flag, never parsed as map).
- `doom/src/engine/`: `doomEngine.js` (loader plus loop driver, stable boundary: `initEngine`, `tickOnce`, `getFramebufferPtr/Width/Height`, `getFrameBufferView`, `queueKey`, `injectTiccmd`, `shutdown`, `onMemoryGrow`), `shim_m1.c` (doomgeneric `DG_*` five-function web shim), `choc_glue.c` (v1.1 SDL2 adaptor exposing the same exports, no SDL surface copy), `simdProbe.js` (validate-probe plus cached binary choice with manual override). - `doom/src/core/`: `loop.js` plus `clock.js` (rAF, accumulator, cap, alpha; `performance.now` only).
- `doom/audio/`: `wadAudio.js`, `mus2mid.js` (both pure, golden-tested), `sfxCache.js` (lazy LRU), `sfxEngine.js` (8-voice pool, steal policy ports `S_GetChannel`, per-frame `setTargetAtTime` update), `musicEngine.js` (OPL3 worklet wrapper, bank load, loop, song switch), `mixer.js` (buses plus compressor plus persisted gains), `audioUnlock.js` (gesture gate plus probe plus overlay hook).
- `doom/src/storage/`: `provider.js` (interface), `storage-opfs.js`, `storage-idb.js`, `storage-local.js`, `saveBundle.js` (export/import schema). ## Risks (residual; owned by milestone)

- Emscripten SDL2 vs custom shim: resolved per phase (shim M1, SDL2 v1.1) behind the stable boundary; same-origin relative paths enforced in both build scripts.
- SIMD/scalar split doubles tested artifacts: owned by M1 loader plus probe with cached choice and manual override; never ship SIMD-only.
- Node-builder inclusion for partial PWAD maps: sized in M1 (`extNodes.js` read support first; internal rebuild only if partial-map uploads fail in M4 testing).
- Hexen dialect: detect-and-report in M1-M4; any playable Hexen path is a later milestone with its own research note.
- Multiplayer: out of scope for all milestones here; the only sanctioned future pattern is the WebSocket socket shim, never raw UDP.
