One-command runbook

git clone https://github.com/Userfrom1995/RandomLabs && cd RandomLabs
sh poolduel/repro.sh --dry-run      # 12-row pilot plan, no PG needed
sh poolduel/repro.sh --pilot        # live pilot: M1-1 + M1-2, one repeat
sh poolduel/repro.sh --full         # full M1 matrix (needs PG 17 + poolers)
sh poolduel/repro.sh --report       # medians + matrix.csv + report.json from raw
sh poolduel/repro.sh --charts       # chart options from committed bundles
sh poolduel/repro.sh --pagemeta     # banner counts from bundles
sh poolduel/repro.sh --site         # pre-rendered master facts
sh poolduel/repro.sh --dossiers     # pre-rendered dossier facts
sh poolduel/repro.sh --supplement   # supplementary-page facts (this section)
python3 -m poolduel.harness.check   # coherence gate (must exit 0)

Serve poolduel/ over HTTP for the live-fetch contract (python3 -m http.server inside poolduel/); opening files directly shows the pre-rendered publish with an honest fetch-failure note.

Per-cell recipe (any maintainer can re-run)

  1. Install PG 17 (PGDG) plus the five pinned poolers per docs/versions.md; Supavisor v2.9.13 per supavisor.md.
  2. Init the dataset at the cell's scale (pgbench -i -s 10, C-block -s 100).
  3. Render the exact config from results/m1|m2|m9/raw/<cell>-<arm>-r<n>.json (pooler_config verbatim).
  4. Run the cell argv from the raw record (warmup discarded, measure kept, per-cell cap enforced by the runner).
  5. Compare your tps/p99 against the committed median band; file a challenge below on mismatch.

Challenge flow

  1. Re-run the cell per the recipe above (same PG 17, same scale, same argv except port).
  2. Open an issue citing the cell ID, arm, your tps/p99 band, and iron (isolate record fields).
  3. Maintainer triages: harness bug (fix + selected-cell re-run), infra flake (re-dispatch), or genuine disagreement (published erratum).
