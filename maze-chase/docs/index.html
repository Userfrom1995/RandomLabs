Maze Chase docs

Unified product documentation for the Maze-Chase Rust game (issue #582). One cohesive product view; no milestone counters or sprint references.

  • Mechanics and stack research: the #552-feel basis, the behavioral contract the engine must meet, and the selected Rust stack with rejected alternatives.
  • Clean-room log and legal guardrails: sources consulted, flagged items with mitigations, naming rationale, release obligations.
  • Identity: naming, branding, maze authorship: the title, cast, terminology allowlist, and the maze authorship log.
  • #552 behavior reference spec: pinned measured values (maze geometry, speeds, clocks, chains, counters) with their #552 source modules.
  • Feature-completeness matrix: the shared binding tracker, one row per mechanic across the engine and all three layers.
  • Visual and interaction design plus design tokens: the glyph system, themes, motion, sound, and settings language every layer shares.
  • Sound identity and mix: the shared 108 BPM score, layered SFX bank, default mix, live fades, per-layer synthesis, and the accessibility twins for every cue.
  • Terminal install and launch guide: install, controls, render tiers, layout, settings/scores files, and troubleshooting (maze-chase-terminal).
  • Desktop install and launch guide: install, controls, gamepad, settings/audio, per-OS packaging, --probe verification with the committed sample screenshot (desktop-probe.ppm), and troubleshooting (maze-chase-desktop).
  • Browser install and launch guide: serving index.html over http, keyboard plus touch controls, DPR-aware canvas, WebAudio unlock, localStorage settings/scores, reproducible .wasm builds, and troubleshooting (browser layer).
  • Reproducible build and release guide: toolchain plus system libraries, engine checks, layer builds, the per-OS packaging matrix, and the clean-checkout release checklist.
  • Release scoreboard: measured tick cost, suite totals, per-OS E2E results, frame budgets, and the native proof record.
  • #552 parity checklist: every pinned reference behavior mapped to its engine table and verify row, fully signed on the Linux run on this tree; the macOS and Windows runs are pre-Pondwake, with fresh reruns tracked in the final sign-off, and the retirement step is recorded.
