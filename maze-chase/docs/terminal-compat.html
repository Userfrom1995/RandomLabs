Terminal compatibility matrix

What the release binary actually does in real terminal emulators, measured by the harness in ../tools/compat/. Every executed row names its committed evidence bundle (../tools/compat/evidence/<row>.json, that row's screenshots, and the row's events.log); every number quoted below re-derives from those files. unverified rows name their executor and why they have not run. Nothing in this table is estimated.

Session: a fixed choreography that boots the game, plays, steers, resizes wide, shrinks below the floor, re-fits, pauses, quits to title, walks help/scores/settings, and quits. On Linux the X11 driver sets real window sizes (measured with xdotool and recorded per event); the macOS Aqua driver skips the resize checkpoints and records the skip. pass means the game process exited on its own and the captures rendered; partial means part of the session measurably fell short (keys landed too late for the process to exit before the harness timeout, or captures failed the render check) with the exact reason in the JSON (exit.killed, light_background_captures); unverified means the row did not execute.

Executed rows (Linux, harness on this build)

All rows ran on 2026-10-21 at checkout 96dc2be2dd4f90498a362c30a587af91b4690f73 (release maze-chase-terminal, SHA-256 ce3b1f91a78f00cbd72d09bd6132b367d027fd504e1e27d56e08ec9bd9f53f86, Rust sources clean); every row below is from that same binary and every row records build.sources_dirty: false. Every number below re-derives from the named JSON and uses true binary units (KiB = 1024 B, MiB = 1024^2 B). Each row records its identity in its own build block (build.commit, build.binary_sha256, build.sources_dirty). The recorded commit is the checkout when the row ran; because a --skip-build run can reuse a binary built at an earlier commit, the binary SHA-256 is authoritative. Each bundle therefore names the exact binary that produced it instead of implying the current head did. The forced kitty truecolor row, the forced Ghostty kitty row, and the forced xterm sixel row record pause_select: 1: they move the pause menu cursor to "Quit to title" before the paused checkpoint, so a forced-tier rerun of an emulator never commits a byte-identical paused capture (their events.log files show the extra Down key at its byte offset). The auto rows keep pause_select 0.

The kitty-graphics pass rows also carry a sprite-palette census per capture (sprite_census in each phase, sprite_visibility.playing_captures_with_sprites at the top level); when placements are on the wire, the collector refuses to sign a kitty-graphics pass without a playing capture containing sprite pixels, and on any bitmap tier (kitty-graphics or sixel) it refuses a pass with no decodable playing capture at all, so a menu-only capture set can never sign one. On Linux and macOS, a pass whose transcript never names the active video tier is refused outright, because the bitmap gates are keyed on the observed tier (Windows rows carry no transcript by design and are graded from the process record and the capture set). The pause hub deliberately freezes the 55%-dimmed board with the actors exempt, so a current paused capture is allowed to carry sprite pixels and sit between 55% and 100% one color: the collector requires the PAUSED card paint in the paused transcript slice, a non-flat paused capture (0.55 <= dominant_share < 1.0) with at least four sprite-palette pixels, and exactly one paused checkpoint, and still refuses a paused capture with no decodable screenshot (missing_paused_capture) or an unpainted deck pane (missing_paused_panel). It also refuses a playing, resized, or refit capture that is >=90% one color on the bitmap tiers (a blank board).

Session view of the tier ladder

  • kitty-graphics is fully playable on a real Kitty and Ghostty. The static board and sprite atlas transmit once per change, placements carry every moving sprite with explicit per-warden z stacking layers (body i below eyes i below body i + 1, mirroring the raster's paint order even when two warden boxes overlap), and steady transmits are silent (q=2), so replies cannot spin the input loop. Both rows exit cleanly, and their playing captures prove sprite visibility by census (no equal-z tie-break can hide the atlas). Measured cost is 21 transmits and 169.9-175.4 KiB of PNG payload per session, against the pre-pipeline flood (a historical 1642 transmits and 348.6 MiB, not re-derivable from the regenerated JSONs). The pause hub freezes the 55%-dimmed board with the actors exempt and transmits no new frame image; the collector therefore accepts sprite pixels in the paused capture but requires the PAUSED card paint, a non-flat capture (0.55 <= dominant_share < 1.0) with at least four sprite-palette pixels, a decodable screenshot, and exactly one paused checkpoint. On every bitmap tier it also refuses a pass with no decodable playing capture, or (on Linux and macOS, whose sessions carry a transcript) one whose transcript never names the active video tier.
  • sixel is fully playable on a real Sixel terminal. The encoder caps its palette at 64 colors and a frame at 2 MiB (with a smaller-palette retry and a cell fallback), and the tier paces at 24 Hz with byte-rate backpressure. Each VT340 row's whole session is 137-138 transmits / 4.25-4.31 MiB.
  • legacy-cells and truecolor-cells are fully playable on every executed cell row (kitty forced cells, xterm default-light, xterm dark).
  • Ghostty is no longer a detection defect: its 1.3.1 build implements the Kitty graphics protocol and answers the live probe when one is sent (a direct pty experiment with the game's exact probe request, ../tools/compat/probe-graphics.py, 2026-10-19; both raw reply captures are committed under ../tools/compat/probe-captures/ with their commands and hashes); TERM_PROGRAM=ghostty and TERM=xterm-ghostty select the graphics path directly and skip the probe on those rows. The watchdog watches the frame write path (steady transmits are silent by design), so a terminal that silently mis-composites cannot be detected; that is why placements carry explicit stacking layers instead of relying on tie-breaking. Both its auto and forced rows pass.
  • Light-background terminals render identically to dark ones: the game now paints the theme's own background on every painted run (the cell tiers no longer rely on the terminal's default background), so the committed default-light xterm row passes with a 1.85% white playing capture and 6.2% at worst, and its dark twin renders the same canvas. The former defect (seven >=98% white captures with the cream chrome text invisible) is pinned by the Unicode backend regression test.

The measured floor is 62 columns by 35 rows (the too-small card names it); below that the game keeps running and re-fits live on the next resize.

Known input limitation: the event source is crossterm's global parser, which holds an unrecognized private CSI sequence (for example ESC [ ? 99999 h) and suppresses key delivery until a completion byte such as u arrives. The harness cannot synthesize a recovery the game does not have, so the limitation is documented in terminal.md and pinned by a PTY regression test; it is not a row-level pass claim.
