Release notes for the first release

Maze Chase is a complete original maze-chase game: one deterministic Rust engine with terminal, desktop, and browser layers. This release includes:

  • The full hunt: a fixed 120 Hz simulation with buffered turns and cornering, four authored warden personalities, scatter and chase waves with reversals, sunseed fright chains at 200, 400, 800, and 1600, pathing eyes, relish bonuses, pursuer stages, a spare wick, and endless level ramp.
  • Four rulesets: classic, time attack, sprint, and fright frenzy, with seeded streams, a replay log, and a state hash.
  • Original art and audio: 11x11 and 21x21 Rill sprites, four distinct wardens, fright masks, six relish icons, three contrast-checked Pondwake themes, layered synthesized sound effects, and five original multi-track tunes at a shared 108 BPM.
  • The terminal game with Kitty graphics, Sixel, truecolor cells, and legacy cells, a live resize floor of 62 by 35, title, help, scores, settings, rebind, and pause surfaces, and machine high scores.
  • The desktop game with a windowed or fullscreen presentation, side HUD, gamepad support, HiDPI handling, and shared settings and scores.
  • The browser game at this site, with keyboard and touch controls, DPR-aware canvas sizing, WebAudio sound, and settings and scores in localStorage.

The measured record for this tree lives in the release scoreboard, the feature matrix, and the parity checklist. The terminal matrix records its executed hosts and evidence separately on Compatibility.

Integrity and reproducibility

  • The browser engine is byte-reproducible from the recorded toolchain: 212,472 bytes, SHA-256 d6dd16bf8038ae5cbde4a81209e4835391dd4ace8a5e3eb1ef37d6b191c62ac0, Rust 1.99.0, no wasm-bindgen, zero imports. A rebuild in CI fails closed if the committed bytes differ.
  • Tarballs and Windows zips are deterministic: sorted entries, fixed owners and modes, and SOURCE_DATE_EPOCH from the commit timestamp. A second build on the same host and toolchain is byte-identical.
  • The macOS disk image records image metadata from hdiutil, so it is checksummed rather than claimed byte-reproducible.
  • Every release publishes one SHA256SUMS.txt for the whole set. The per-host toolchain records are folded into the release notes.
  • Binaries are unsigned. SmartScreen and Gatekeeper warnings are expected and are not a signature claim.

Version and tag contract

A release tag is exactly maze-chase-v<workspace version>. A candidate adds a numeric suffix such as -rc.1. Before any build, the pipeline checks that the tag matches the workspace version and fails closed on a mismatch. A branch dispatch is allowed as a non-release build. Published tags are never moved or reused.

# tag build (release)
bash maze-chase/packaging/release/check-tag.sh "$GITHUB_REF_NAME"

# branch dispatch (non-release)
bash maze-chase/packaging/release/check-tag.sh "$GITHUB_REF_NAME" --allow-branch

Release process

  1. Start from a clean checkout with the toolchain and system libraries from the release guide.
  2. Run cargo test --workspace --locked and the 19-row deterministic verify harness. Stage and smoke each applicable packaging row on its native host.
  3. Check tag parity, rebuild the committed wasm, and confirm every checksum.
  4. Publish the artifacts and notes through the release workflow, as a prerelease for a candidate tag.
  5. Before a stable tag, re-run every per-OS install, upgrade, and uninstall row and re-sign the compatibility matrix.

The complete checklist, commands, and known constraints are in the release guide. Upgrade and uninstall instructions are in the installation guide.
